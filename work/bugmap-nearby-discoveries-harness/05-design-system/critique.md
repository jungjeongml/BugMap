### 발견

- **중요 · 위치 권한 복구 · NEAR-03.** 최초 `components.json`의 `RadiusChip`은 위치 확인이 불가능하면 “기존 선택을 유지”한다고 명시한다. 승인된 구조는 3 km가 선택된 상태에서 반경을 바꾸려다 위치 확인에 실패한 경우에도 거부·취소·실패 후 `전체`로 돌아가고 카드 거리와 지도 경계를 숨기도록 정의한다. 구현자가 시스템 문구를 따르면 위치가 없는 상태에서 거리 칩이 선택된 채 남아 실제 목록 조건을 잘못 전달할 수 있다. 확인 성공 시에 요청한 반경을 적용하고 거부·취소·실패 시 `전체`를 표시하는 규칙을 컴포넌트와 생성된 디자인 문서에 동일하게 적는다. [상태표](../03-structure/states.csv) · [흐름](../03-structure/flows.mmd)
- **중요 · 반응형·접근성 규칙.** 최초 `DESIGN.md`는 최소 44×44px과 Lucide 사용을 명시하고 컴포넌트 좌표는 390×844 기준으로 제공한다. 더 좁은 영역이나 글자 확대에서 카드의 이름·거리·발견 일시를 유지하는 방법, 고정 복귀 버튼의 안전 영역 처리, 스크린리더에 카드 메타데이터와 칩 선택 상태를 전달하는 규칙이 빠져 있다. `copy.json`의 카드 접근성 문구에는 곤충명과 열기 동작만 들어 있다. 이대로 이관하면 구현자마다 잘림과 낭독 동작이 달라질 수 있다. 390×844 대표안에 추가 화면을 요구할 필요는 없다. 기기 안전 영역과 긴 텍스트의 레이아웃 기준, 낭독할 필드와 선택 상태의 전달 순서를 시스템에 명시하면 된다. [Stage 05 기준](../../../docs/design-harness.md)
- **경미 · 확장 패널 손잡이 · NEAR-01.** 최초 `NearbySheet`에는 아래로 드래그해 복귀하는 동작과 `내 주변 발견 접기` 레이블이 있다. 승인된 대표 복귀 경로는 `지도 보기`다. Stage 06에서 별도 제스처 구현까지 필요한지 혼동할 수 있으므로 현재 범위의 복귀 동작을 컴포넌트에 명시한다. [프로토타입 범위](../03-structure/flows.mmd)
- **경미 · 기본 상태의 왕잠자리 사진 · NEAR-04.** 두 번째 카드의 88×88px 이미지에서 날개와 몸통이 수초와 겹친다. 이름과 필수 정보는 읽히지만 목록을 사진으로 훑을 때 다른 두 카드보다 피사체를 알아보기 어렵다. 필요하면 피사체를 더 가까이 자른 뒤 실제 88px 렌더에서 확인한다. [기본 상태 캡처](captures/390x844-default.png)

### 유지할 점

- 두 캡처 모두 검색, 거리 칩, 기록 목록 순서가 분명하다. 기존 메인 지도와 검색 문구·필 모양·네 탭이 이어지고 지도 탭만 선택된다. `지도 보기`는 두 상태에서 같은 위치에 보인다.
- 기본 화면의 세 기록은 실제 발견 일시 최신순으로 보인다. `3 km 이내` 화면에는 0.8 km와 경계 예시 3.0 km가 남고 4.6 km는 빠진다. 선택 칩에는 윤곽·면·굵기 차이가 있고 관찰과 채집은 글자로 구분된다.
- 렌더 보고서에 기록된 모든 주요 조작 영역은 44×44px 이상이며 겹치지 않는다. 보고서가 측정한 텍스트 대비의 최솟값은 두 상태 모두 6.43:1이다. 사진·서체·라이선스 파일의 현재 해시는 자산 매니페스트와 일치하며 사진 세 장의 저작자와 이용 조건도 원본 페이지에서 확인했다. ### 미검증과 재검토 조건

Figma 노드, 기존 지도 드래그 진입과 복귀, 스크롤 중 고정 버튼, 칩 전환과 복귀는 실제 조작하지 않았다. 지도·목록의 실시간 상태 공유, 검색과 위치 복구, 기존 상세 경로, 스크린리더 동작은 구조 또는 시스템 문서의 범위에서만 대조했다. 원격 Figma에서 기존 노드와 연결 보존 및 사진 출처 전달도 확인해야 한다. 수정본 재검토는 새 인스턴스에서 현재 입력 해시와 실제 캡처로 진행한다. 검토 중 파일 수정 및 사람 승인·리뷰 명령 실행은 없었다.

## 수정본 재검토 — `needs_revision`

### 검토 범위와 버전

정식 PRD·수용 기준, 상태와 흐름, 승인 와이어프레임 및 하네스 05단계 기준을 대조했다. 와이어프레임 SHA-256은 `95d23946eaa1580454e134137442af4e90d847f07fae0671a0b13ec7b83e2013`이다.

스테이징의 `components.json` SHA-256 `95017bcf37a5641351bc5ce806760a83a93551d2975357c8da4f6bdf619593c7`, `review.md` SHA-256 `aad1eadbec4f6b844a9e09e25adc5bfa00423bbc4ce29f50e7a4ac3763685ef8`을 확인했다. 위 표에 기록된 세 PNG를 이미지 도구로 다시 열었다.

### 발견과 유지할 점

- **경미 · 05단계 문서 보완.** 공통 기준은 카드 모서리 32px, 내부 사진 모서리 20–24px를 명시하고 다른 값을 쓸 때 이유와 범위를 요구한다. 목록 시안은 카드 20px, 사진 13px를 적용했지만 예외 근거가 없다. `review.md`에 두 값과 내 주변 발견 목록 한정 적용 근거를 적으면 현재 시각 시안을 유지할 수 있다. [공통 기준](../../../docs/DESIGN.md#shapes) · [토큰](tokens.json)
- 검색·거리·목록 순서와 기존 메인 지도의 다크 패널, 검색 필, 네 탭이 연속된다. 두 캡처에서 지도 탭만 선택되고 지도 보기 버튼과 탭 위치가 같다. 3 km 상태는 4.6 km를 제외하고 경계의 3.0 km를 유지한다. `render-report.json`의 상태별 13개 및 교차 상태 2개 검사도 통과했다.
- 위치 확인 성공 시 요청한 반경 적용, 거부·취소·실패 시 전체 목록 복귀와 거리·지도 경계 숨김이 컴포넌트와 구조 문서에서 일치한다. 좁은 화면의 칩 스크롤, 큰 글자의 카드 줄바꿈, 안전 영역과 카드 읽기 순서도 제품 적용 기준에 명시됐다.

### 미검증

05단계 근거는 390×844 정적 시안 두 장이다. SVG의 카드 버튼 `aria-label`은 종명과 열기 동작만 지정하므로 제품 문서가 명시한 카드 메타데이터 전체 낭독은 실제 스크린 리더에서 확인해야 한다. 다른 너비와 글자 배율도 미검증이다. 06단계에서 실제 Figma 노드와 기존 지도 보존을 확인하고 손잡이 드래그 진입, 지도 보기 복귀, `전체 ↔ 3 km 이내`를 직접 조작해야 한다. 위치 복구·반경 공유·검색·상세는 승인된 제품 흐름으로 대조할 항목이다.

### 근거

- 검색 → 거리 선택 → 기록 목록의 순서가 명확합니다. 3 km 이내를 선택한 캡처에서 4.6 km 기록은 제외되고 경계에 있는 3.0 km 기록은 남습니다. 결과 수는 3개에서 2개로 바뀌며 ‘지도 보기’와 네 탭의 위치는 두 상태에서 같습니다.
- 메인 지도의 어두운 패널, 검색 문구와 형태, 네 탭, 지도 탭 단독 선택이 이어집니다. 기록 사진과 이름, 관찰·채집 유형, 공개 지역, 발견 일시, 거리에 잘림이나 겹침이 보이지 않습니다.
- 공통 디자인 문서는 이유와 적용 범위를 명시한 화면별 예외를 허용합니다. 카드 20px와 썸네일 13px는 작은 사진의 모서리 잘림을 줄이고 반복 카드의 경계를 유지하려는 목록 전용 값입니다. 시트는 공통 32px를 사용합니다.
- 경미한 관찰로, 전체 상태의 왕잠자리 사진은 88px에서 잎과 날개의 색이 비슷해 다른 두 사진보다 피사체를 빠르게 구분하기 어렵습니다. 곤충명과 기록 정보는 읽을 수 있습니다.

### 미검증

실제 Figma 진입·복귀·필터 전환과 기존 노드 보존, 네이티브 스크롤·검색·위치 권한·반경 공유, 기기별 글자 배율과 스크린 리더 동작은 후속 검증 범위입니다. 읽기 전용으로 검토했으며 파일 수정과 승인 기록은 수행하지 않았습니다.
