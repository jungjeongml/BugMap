# 05 첫 로그인 후속 단계 권고

| 요구사항 | 관찰 | 승인 범위 안의 적용 |
|---|---|---|
| LOGIN-05-01 | 원본은 한 화면에서 앱 목적과 로그인 선택지를 차례로 보여 준다. | 대상의 `login/default` 한 장을 390×844로 계획한다. 로고, 제목·부제, 지도 관찰 사례, 버튼, 약관 순서를 유지한다. |
| LOGIN-05-02 | 관찰 요소는 중간에서 뚜렷하고 상단 로고와 하단 로그인 영역 쪽 지도 명도는 낮다. 노드에서 지도 이미지와 선형 페이드가 분리되어 있다. | 지도와 상하 페이드를 합성한 전면 배경 PNG를 등록하고 파일 출처·SHA-256을 연결한다. 캡처 비교에서 상하 연결, 로고 주변, 관찰 영역의 가시성을 확인한다. 별도 콘텐츠를 가리는 패널을 추가하지 않는다. |
| LOGIN-05-03 | 원본의 128×39.7 규모 로고는 연두색 벡터 경로로 보인다. | `BugMap-logo-vector`의 배경이 없는 상태와 `#C5EE79`, 형태·비율을 편집 가능한 레이어에서 검수한다. |
| LOGIN-05-04 | 원본 버튼 순서와 색은 카카오 노랑, 네이버 흰색, Apple 검정이다. 외곽은 둥글고 노드 크기는 각각 358×48이다. | PRD에 명시된 358×48, 모서리 설정 32px, 최소 44×44 터치 영역 기준, 원본 순서와 국문 레이블을 검수 항목으로 옮긴다. 버튼 외곽과 제공자 내부 자산을 구분하고 공식 표식 비례를 유지한다. |
| LOGIN-05-05 | 원본의 밝은 제목과 작은 지도 라벨·약관 사이에 위계가 있고 네이버와 Apple에 얇은 경계가 있다. 각각의 공식 참조는 제공자 표식·레이블의 보존 근거를 제공한다. | 주요 문구, 벡터 로고, 버튼 외곽, 약관은 편집 가능한 상태로 두고 콘텐츠 컨테이너에 오토레이아웃을 적용한다. 실제 선택한 공식 자산의 개별 파일·URL·해시를 연결한다. 일반 UI 아이콘은 Lucide에서 선정하고 상태 표시는 시안의 시스템 영역으로 다룬다. 대상 캡처에서 대비, 경계, 잘림·겹침, 상하 안전 영역을 확인한다. |
| LOGIN-05-06 | 트리에 별도 06 작업 프레임이 중첩되어 있고 대상 기존 02 프레임의 제작 전 기록이 있다. | 원본 `134:1239`과 대상 기존 `7:2`의 보존을 제작 전후 증거로 대조한다. 이를 위한 조회는 후속 제작·검증 단계에서 수행한다. |

## 제품 구현 전에 결정할 항목

- **카카오.** 공식 커스텀 컨테이너의 12px 기준과 원본 재현의 32px 설정이 다르다. 현재 시안은 승인된 32px을 사용한다. 실제 적용 전에 공식 버튼 외곽 또는 허용된 구현 변형을 확인한다. [카카오 디자인 가이드](https://developers.kakao.com/docs/ko/kakaologin/design-guide#카카오-로그인-버튼)
- **네이버.** 공식 자료는 흰 완성형을 제공하고 타사 컬러 버튼과 나란히 둘 때는 녹색 완성형을 권장한다. 현재 시안은 원본의 흰색을 유지한다. 실제 적용 전에 병행 조건에서 녹색 권장형과 대비를 검토한다. [네이버 디자인 가이드](https://developers.naver.com/docs/login/bi/bi.md)
- **Apple.** 공식 시스템 검정 스타일은 밝은 배경에서 사용한다. 현재 시안은 원본의 어두운 배경, 검정 버튼, 얇은 경계를 유지한다. 실제 적용 전에 어두운 배경의 흰 시스템 스타일 또는 공식 커스텀 버튼 조건과 대비를 검토한다. [Apple HIG](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple.md)

이 항목들은 승인된 정적 시안의 원본 재현 기준과 제품 구현 시의 제공자 요건을 추적하기 위한 것이다. 현재 단계의 근거는 버튼 외형 비교와 출처 검토까지다. 제공자 심사, 네이티브 인증, 지도 SDK, 실제 탭·스크롤·스크린리더, 후속 상태는 이 리서치에서 검증하지 않았다. 제품 요구사항이나 05 시안의 범위 변경은 제안하지 않는다.
