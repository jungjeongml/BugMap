## 기록 3

이전 3건 시안의 JSON 화면과 생성 SVG·PNG를 그대로 재사용했다. 선택 마커 41:394의 중심은 (300, 333)이다. 패널은 y=396부터 448px로 화면 높이의 53.1%를 차지한다. 사진·이름·발견일이 포함된 358×104px 행 세 개가 모두 보이고 마지막 행은 y=796에서 끝난다. y=810부터 34px는 하단 안전 영역이다. ## 기록 7과 목록 스크롤

- 선택한 기록 7 마커 41:390의 중심은 (90, 189)이다. 기록 3은 다른 묶음으로 보인다. Mapbox 로고는 왼쪽, 출처 버튼은 오른쪽에 둔다. 출처 버튼은 (338, 320)에서 44×44px이고 기록 3 터치 영역과 가로 6px 간격이다. 두 선택 상태에서 GPS·기록 작성은 패널을 닫으면 같은 카메라의 기본 지도에서 복원된다.
- 패널은 y=376부터 468px다. 위쪽 두 모서리의 반경은 32px이며 화면 바닥까지 닿는다. 제목과 48×48px 닫기 버튼은 고정한다. 기준 글자는 제목 24px, 이름 18px, 날짜 14px로 명세했다. CLI 출력의 문구는 14px로 렌더링된다.
- 목록만 y=448 이상 y=810 미만의 영역에서 세로로 스크롤한다. 358×104px 행, 행 사이 8px, 80×80px 사진을 동일하게 쓴다. 첫 세 행은 y=448, 560, 672에서 시작하며 각각 전체가 보인다. 네 번째 행과 사진 자리도 같은 크기로 그린 뒤 목록 하단 y=810에서 실제 SVG 클립으로 잘랐다. 행 위쪽 26px(¼)와 사진 위쪽 14px가 바닥선이나 아래 모서리 없이 경계까지 이어진다. 이름·날짜와 사진 자리 레이블은 첫 위치의 캡처에서 숨긴다.
- 일곱 행의 순서와 상세 목적지는 `record-overflow-demo-01`부터 `record-overflow-demo-07`까지다. 첫째·둘째가 예시 공개 좌표를 공유하고 ID는 다르다. 행별 이름·발견 날짜·사진 자리와 스크롤 치수는 [JSON](wireframes.json)에 있다. 7건의 계산된 스크롤 끝은 `scrollTop=414`이며 일곱째 행 전체가 y=706 이상 y=810 미만에 놓인다. 다른 묶음을 선택하면 강조와 건수·목록이 함께 바뀌고 스크롤은 처음 위치로 돌아간다.
- 작은 화면이나 큰 글자에서는 이름을 줄바꿈하고 행 높이를 내용에 맞춘다. 목록을 스크롤해 모든 행의 이름·날짜를 읽고, 안전 영역 앞에서 마지막 행을 누를 수 있게 한다. [7건 SVG](main-map/cluster-selected-overflow.svg)

## 확인한 결과

정식 하네스 `check`에서 개정 PRD와 리서치가 통과했음을 확인했다. 승인 범위와 구조의 제작 상태 두 개를 JSON·SVG/PNG와 대조했다. 공식 `wireframe` 명령을 임시 Chrome 프로필에서 실행해 종료 코드 0으로 두 PNG와 SVG를 생성했다. 두 PNG를 직접 열어 각각 선택 마커, 다른 묶음, 출처, 제목과 닫기, 세 행 및 하단 안전 영역을 확인했다. 7건에서만 네 번째 행 상단이 보인다. 두 화면에서 처음에 전부 드러난 버튼 7개씩의 최소 44×44px와 상호 비겹침을 확인했다. 7건의 일부만 보이는 네 번째 행은 첫 위치의 터치 영역 검수에서 제외했다. 네 번째부터 일곱 번째 행의 실제 도달과 전체 터치는 후속 스크롤 검증에서 확인한다. [생성 리포트](wireframes-report.json)

## CLUSTER-07의 정확히 4건 HTML 검수

7건과 같은 390×844, y=376·높이 468px 패널, y=448~810 목록, 358×104px 행·8px 간격·80×80px 사진을 사용한다. 동일 데이터의 첫 네 기록만 입력한다. 검증용 HTML의 수용 절차는 아래와 같다.

1. 초기 위치에서 세 행 전체와 네 번째 행 상단 26px 이하만 보이고, 네 번째 이름·날짜는 가려지는지 확인한다. 시작 PNG를 남긴다.
2. 제목과 닫기가 고정된 상태에서 목록을 끝까지 스크롤한다. 마지막 행 전체가 하단 안전 영역 위인 y=706 이상 y=810 미만에 보이는지 확인하고 끝 PNG를 남긴다. 기준 치수의 계산된 `scrollTop`은 78이다.
3. 마지막 행을 누른 뒤 HTML이 수신한 기록 ID가 `record-overflow-demo-04`인지 확인하고 시작·끝 PNG와 수신 결과를 함께 기록한다.

## 후속 검증

실제 동작은 Figma와 HTML에서 별도로 확인한다. Figma에서는 두 마커의 진입·닫기·같은 카메라 복원, 기존 레이어와 연결, 7건 목록 스크롤 및 마지막 행 전체 노출과 선택을 조작한다. 기존 출처 링크가 있으면 재사용해 열기·닫기를 확인하고, 링크가 없으면 앱에서 SDK 출처 열기를 검증한다. 실제 지도·사진·공식 로고와 긴 이름·큰 글자, 접근성 포커스와 실기기 안전 영역도 후속 확인 범위다. 이 단계의 증거는 390×844 정적 PNG와 명세다.
