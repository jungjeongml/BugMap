# 기록 묶음 선택 디자인 시스템 검수

## 승인 입력과 시각 방향

정식 저장소의 공식 `check`에서 PRD·리서치·구조·와이어프레임 통과와 와이어프레임 승인 `ebec90a2-123f-46c4-88c1-b0979cdeccbe`를 확인했다. 와이어프레임 JSON·PNG, 기존 Figma 지도 캡처·토큰의 SHA-256은 [자산 목록](assets-manifest.json)에 기록했다. 기존 390×844 지도 캡처와 승인된 와이어프레임 PNG를 열어 비교했다.

같은 서울숲 카메라, 지도 지형·라벨, 기록 7·5 및 내 위치를 재사용했다. 선택한 기록 3은 중심 (300, 333)과 64×44px 조작 영역을 유지하고 연두색 2px 외곽선을 더했다. 선택 표식은 원형 하늘색 내 위치 점과 형태가 다르며 선택 상태도 접근성 이름과 상태로 전달한다. 기존 GPS와 작성 버튼은 y=536, 출처 영역은 y=482~526에 둔다. 공식 Mapbox 로고는 원래 치수 88×23px로 x=14, y=492에 있다.

관찰 기록 패널은 y=592부터 화면 바닥까지 차지한다. 위쪽 좌우 반경은 32px, 하단 모서리는 0이다. 제목은 Pretendard Bold 20px, 이름은 Bold 15px, 발견일은 Medium 12px를 사용한다. 이름과 날짜는 한 열에 위아래로 놓고, 44px 썸네일은 왼쪽, 행 이동용 화살표는 오른쪽에 둔다. 승인본의 세 이름과 발견 날짜를 그대로 사용한다. ## 390×844 검수

Chromium에서 로컬 SVG를 1×로 렌더한 PNG를 디스크에서 직접 열었다. 지도 위 출처와 두 조작부, 선택 마커, 패널의 제목과 닫기, 세 사진·이름·날짜·화살표가 동시에 보인다. 사진 세 장은 서로 다른 개별 PNG 레이어이며 지도와 Mapbox 로고는 별도 SVG다. 패널 바탕·선택 테두리·행·아이콘·텍스트는 각각 편집 가능한 레이어로 재구성할 수 있게 나뉘어 있다.

공식 디자인 단계 검사에서 입력 JSON과 CLI 생성 문서 및 증거 해시가 일치했다. Chromium CDP로 표시 텍스트 16개가 Pretendard 500/700과 토큰의 크기, 색, 문구를 쓰는지 확인했다. 텍스트와 세 사진은 서로 겹치거나 영역을 넘지 않았다. 조작 영역 10개는 승인 좌표와 일치하고 최소 44×44px이며 서로 겹치지 않는다. 패널의 닫기와 지도 출처는 각 44×44px, GPS와 작성은 높이 48px, 각 행은 358×51px다. 세 번째 행은 y=804에서 끝나고 하단 안전 영역은 y=810에서 시작한다. 검수 PNG SHA-256은 `2d9ea572d7227c2725004ba2f5c62d1966ba4f13736d29704a1aed02a59ed970`이다.

## 편집 구조와 긴 글자 대응

Figma 제작 시 지도·지도 조작부·주변 기록 패널·기록 목록·내 위치·시스템 UI를 그룹으로 구성한다. 텍스트 노드의 카피와 논리 순서를 유지하고, 날짜와 이름 및 사진은 같은 행 그룹에 넣는다. 행별 `recordId`/상세 ID 대응은 `photo-sources.json`에 있다. 01·02는 같은 공개 좌표 그룹의 별도 기록이다. 패널 초점 순서는 닫기 → 첫째 → 둘째 → 셋째다. 패널을 닫으면 같은 지도 카메라에서 검색·탭을 복원하고 시연 진입 마커로 초점을 돌린다. 다른 묶음을 선택하면 강조·건수·목록을 동일 선택을 기준으로 함께 전환한다.

대표 PNG는 기본 글자 크기에서 세 행이 모두 보인다. 앱에서 긴 한글 이름은 먼저 어절에서 줄바꿈하고 한 어절이 가용 폭을 넘으면 글자 경계에서 줄바꿈한다. 행 높이는 51px 이상으로 유연하게 늘리고 날짜는 독립 줄에 둔다. 닫기 영역과 겹치지 않게 제목도 줄바꿈할 수 있어야 한다. 확대 시 목록에 가용 높이를 배정해 필요하면 목록 내부를 스크롤하고 현재 선택 마커, 지도 출처, 닫기, 하단 안전 영역을 유지한다. 200%에서 긴 한글 예시 폭 573.87px과 날짜 폭 117.96px을 브라우저에서 측정했다. 254px 텍스트 열에서 이름 줄바꿈이 필요하고 날짜는 한 줄에 들어간다.

기존 Figma 지도와 같은 Noto Sans KR 500/700을 Pretendard가 없는 환경의 대체 서체로 지정했다. Figma에서는 해당 환경에서 글꼴을 확인한 뒤 행 너비와 날짜 위치를 다시 확인한다.

## 요구사항과 검증 범위

| 요구사항 | 이 단계의 증거와 남은 검증 |
| --- | --- |
| CLUSTER-01 | 지도, 선택 마커와 관찰 기록 패널을 한 장에서 확인했다. 기존 마커와 새 프레임의 프로토타입 연결은 Figma 단계에서 확인한다. |
| CLUSTER-02 | 제목 3건, 사진 3장, 세 이름 및 발견일과 이름 모름 표기를 확인했다. |
| CLUSTER-03 | 행별 기록 ID와 상세 목적지 대응, 터치 영역을 확인했다. 전체 사진·메모 상세의 동작은 명세 범위다. |
| CLUSTER-04 | 닫기 영역을 확인했다. 같은 화면 복귀는 Figma 단계에서 확인하고 다른 묶음 갱신은 명세 범위다. |
| CLUSTER-05 | Mapbox 로고와 출처 영역의 노출 및 위치를 확인했다. 사용 가능한 기존 출처 연결은 Figma에서 확인하고, 앱에서는 SDK 출처의 열기와 닫기를 확인한다. |
| CLUSTER-06 | 편집 구조와 자산을 명세했다. Figma Page 1 노드와 기존 프레임·연결의 대조는 Figma 단계에서 확인한다. |

대표 SVG는 정적 시안이다. Figma 또는 앱에서 눌림·키보드 초점·다른 묶음·GPS·작성·실제 출처와 네이티브 큰 글자 레이아웃의 동작을 확인해야 한다. 로딩·빈 결과·오류의 화면 범위는 승인 구조의 상태 표에 따른다.
