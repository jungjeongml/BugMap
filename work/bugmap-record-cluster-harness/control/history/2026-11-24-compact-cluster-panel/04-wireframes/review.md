# 기록 3 마커 선택 와이어프레임 검수

로그인 후 기존 발견 지도에서 기록 3을 누른 390×844 상태 한 장을 검토했다. 패널에서는 제목과 닫기, 세 기록의 사진·이름·발견일 순으로 확인할 수 있다. 제목의 3건은 선택한 마커의 공개 기록 수를 뜻한다. [PNG](captures/main-map/cluster-selected.png) · [SVG](main-map/cluster-selected.svg) · [흐름](../03-structure/flows.mmd)

## 배치 결정

- 기존 지도 캡처와 와이어프레임을 열어 대조했다. 진입 지도 `41:81`의 카메라와 마커 `41:394`의 기준 중심 (300, 333)을 선택 상태에도 사용했다. 저충실도에서 테두리로 선택을 구분하고, 기록 마커와 내 위치는 각각 글자가 있는 배지와 점으로 표시했다. 후속 시안에서는 기존 다크 팔레트의 기록 강조 역할을 사용하고 공식 지도 로고와 스타일을 재사용한다. [원본 지도 PNG](../../bugmap-main-map-harness/06-figma/captures/main-map-default.png)
- 패널 상단을 y=592에 두고 제목, 닫기, 세 행, 하단 안전 영역에 252px를 사용했다. 기존 발견 지도 패널의 상단 반경 32px를 좌우 위쪽 모서리에 적용했다. 패널 하단은 화면 바닥 y=844까지 닿는다. 썸네일과 한글 이름, 발견 날짜를 담는 행은 모두 51px씩 사용했다. 마지막 행은 y=804에서 끝난다. y=810부터 34px는 홈 인디케이터를 포함하는 시안의 안전 영역이다.
- 출처와 GPS·기록 작성의 기존 좌우 위치와 위아래 순서를 유지했다. 패널 상단이 64px 올라간 만큼 두 조작부 줄을 각각 64px 올렸다. GPS·기록 작성을 숨기는 안도 검토했으며, 지도 문맥과 기본 조작을 같은 순서로 알아볼 수 있고 선택 마커·지도 라벨·출처·패널과 겹치지 않아 노출을 유지했다. 시연에서 두 조작의 역할은 위치를 보여주는 데까지다. [리서치 제안](../02-research/recommendations.md)
- 예시 기록의 날짜와 공개 좌표 그룹은 시연용이다. 세 행에는 한글 이름과 발견 날짜를 표시했다. 긴 한글 이름과 큰 글자에서 날짜 및 세 행이 보이는지는 후속 시각 검수 항목이다. 이름의 표시 형식·발견일 정렬에 대한 제품 정책은 기존 명세를 따른다. 썸네일은 각 44×44의 저충실도 자리표시자다. 후속 자산 선정 시 저장소의 사진 출처와 사용 조건을 확인한다.

| 행 | 기록 ID 및 상세 목적지 ID | 시연용 공개 좌표 그룹 | 표시할 이름과 발견일 |

## 390×844 검수 결과

정식 저장소의 하네스 `check`에서 PRD와 리서치의 통과를 직접 확인했다. 구조 목록의 제작 범위, JSON 및 하네스 출력은 모두 `main-map/cluster-selected` 한 장으로 일치한다. 스테이징에서 공식 `wireframe` 명령을 임시 Chrome 프로필로 실행해 SVG와 PNG를 생성했다. 기본 샌드박스에서 Chrome이 종료됐고, 같은 명령을 승인된 실행 경로에서 재실행해 종료 코드 0으로 완료했다. [생성 리포트](wireframes-report.json)

생성 PNG를 직접 열었다. 강조 마커는 지도 자리 안의 내 위치 점과 구분되고, Mapbox 및 ⓘ는 패널과 GPS·기록 작성 버튼 위에서 보인다. 패널 위쪽 두 모서리의 곡선과 화면 바닥에 닿는 하단을 확인했다. 제목과 닫기는 곡선에 닿지 않고 서로 떨어져 보인다. 세 행의 썸네일·이름·날짜 및 행 화살표가 첫 화면에서 분리되어 보이며, 각 행의 이름과 날짜는 서로 겹치지 않고 사진 옆에서 읽힌다. 세 번째 행은 y=804에서 끝나고 y=810부터 시작하는 하단 안전 영역까지 6px 여백이 있다. 홈 인디케이터는 하단 안전 영역 안에 보인다.

| 대상 | x, y | 범위 |
| --- | --- | --- |
| 지도 출처 | 330, 482 | 44×44px |
| 닫기 | 330, 596 | 44×44px |
| 첫째 행 | 16, 645 | 358×51px |
| 둘째 행 | 16, 699 | 358×51px |
| 셋째 행 | 16, 753 | 358×51px |

JSON 좌표를 비교해 10개 버튼의 크기와 상호 비겹침 및 상하 안전 영역을 확인했다. 패널 안의 읽기 순서는 제목, 닫기, 첫째 행, 둘째 행, 셋째 행이다. 패널 내부의 상호작용 순서는 닫기 다음 세 행이다. 실제 접근성 트리와 포커스 동작은 구현에서 확인한다.

## 요구사항별 후속 확인

| 요구사항 | 확인한 증거와 후속 단계 |
| --- | --- |
| CLUSTER-01 | 390×844 캡처에서 강조 마커, 지도 영역과 대체 패널이 보인다. Figma에서 기존 `41:394` 탭 후 선택 화면으로 전환되는지 조작한다. |
| CLUSTER-02 | 제목에 3건, 세 행에 썸네일 자리, 곤충 이름과 발견일을 확인했다. 이름 미확인 표기를 확인했다. 실제 사진과 최종 글꼴에서 긴 한글 이름과 큰 글자에서도 날짜와 세 행이 보이는지 Figma 캡처로 확인한다. |
| CLUSTER-03 | 세 행의 터치 영역과 별도 기록 ID 목적지를 기하 검수와 구조 명세에서 확인했다. 같은 공개 좌표 그룹인 첫째·둘째의 상세 목적지는 별개다. 사진 전체와 메모의 실제 상세 진입은 앱에서 확인한다. |
| CLUSTER-04 | 닫기 영역과 원본 및 선택 지도 사이의 카메라 복귀 규칙을 확인했다. Figma에서 닫았을 때 같은 카메라와 하단 검색·탭이 복원되는지 조작한다. 다른 묶음으로 바꾸는 동작은 강조·건수·목록을 함께 갱신하는 구조 명세를 따른다. |
| CLUSTER-05 | 출처 버튼의 44×44 영역과 로고 자리의 가시성을 확인했다. Figma에서 원본 공식 로고와 버튼 영역을 확인하고 기존 출처 연결이 있으면 열기와 닫기를 조작한다. 연결이 없으면 열기는 Mapbox SDK를 적용한 앱에서 검증한다. |
| CLUSTER-06 | 제작 상태 한 장의 JSON·SVG·PNG를 확인했다. Figma 단계에서 Page 1의 새 편집 가능 프레임, 진입·복귀 및 원본 레이어와 기존 인터랙션을 대조한다. |

시각 검수 범위는 로컬 390×844 정적 캡처다. 실제 지도·공식 로고와 실기기 안전 영역, Figma 연결, 원본 노드 및 인터랙션, SDK 출처 열기, 지도 조작, 실제 접근성 트리·스크롤 및 제품의 로딩·빈 결과·오류 복구는 이후 검증 범위다.
