# BugMap 기록 3 마커 선택 화면

로그인 후 발견 지도를 보는 사용자는 `기록 3`을 눌러 선택한 마커 주변에서 무엇이 발견됐는지 확인할 수 있다. 지도에 선택 위치를 남기고, 하단에서 세 기록의 사진·이름·날짜를 한눈에 보도록 한다.

## 제작 범위

- [BugMapHarness Page 1](https://www.figma.com/design/Dan8qlRM20XPkk7Mtd5riw/BugMapHarness?node-id=0-1)에 한국어 모바일 `main-map/cluster-selected` 프레임 하나를 제작한다. 검수 기준은 390×844이며, 기존 메인 지도 `41:81`과 `기록 3` 마커 `41:394`를 진입점으로 사용한다.
- 선택한 묶음 마커를 강조하고, 지도와 마커가 계속 보이는 상태에서 하단 메뉴바 자리에 `이 주변 관찰 기록 3건` 패널을 연다. 건수와 목록의 범위는 선택한 마커에 속한 공개 기록이다.
- 패널에는 닫기와 기록별 사진 썸네일, 곤충 이름, 실제 발견 날짜를 표시한다. 예시의 세 건은 첫 화면에서 확인할 수 있어야 한다. 이름이 확인되지 않았을 때는 제품의 기존 문구 `이름 모름`을 적용한다.
- 행을 누르면 해당 기록 상세의 전체 사진과 메모로 이어진다. 공개 좌표가 같은 기록도 서로 다른 기록 ID를 가진 행으로 표시하고 각각의 상세에 대응시킨다. 기록 상세 화면 자체, 데이터 조회와 위치 산정은 이번 제작 범위 밖이다.
- 프로토타입에서는 `기록 3 → 선택 패널 → 닫기 → 같은 지도`를 확인한다. 다른 묶음으로 바꿀 때는 선택 강조와 목록이 함께 바뀌는 규칙을 명세한다. 다른 묶음의 별도 프레임은 제작 범위 밖이다.

## 화면과 동작의 수용 기준

- 사용자 여정은 발견 지도 → 묶음 선택 → 세 기록 확인 → 상세 진입 또는 닫기다. 닫으면 보고 있던 지도 위치에서 메뉴바가 다시 표시된다.
- 패널 위에 선택 마커, 지도, Mapbox 로고와 출처 버튼이 보여야 한다. 닫기·기록 행·출처 버튼의 터치 영역은 각각 최소 44×44다. 제품에서 출처 버튼을 누르면 지도 출처를 열 수 있어야 한다. 기존 Figma 출처 인터랙션이 있으면 선택 화면에서 재사용해 조작을 확인한다. 기존 인터랙션이 없으면 이 시안에서는 터치 영역과 가려짐을 확인하고, 출처 열기는 앱 검증 항목으로 기록한다.
- 390×844 Figma 내보내기에서 목록의 세 행, 긴 이름의 잘림·겹침, 마커와 패널의 가시성을 확인한다. 실제 프로토타입 검증과 캡처에 의한 시각 검증은 각각 기록한다. [수용 기준 표](requirements.csv)

## 참고 자료와 남은 설계 판단

사용자가 첨부한 Kyro 광교호수공원 화면에서 지도·선택 위치·하단 정보 패널이 동시에 보이는 구성을 참고한다. BugMap의 정보 순서는 기록 사진·이름·날짜를 중심으로 잡는다. 패널 높이, GPS·기록 작성 버튼의 배치, 세 예시의 사진 자산과 표시 순서는 후속 설계에서 검토한다. 이 단계에서 추가로 확정해야 할 제품 범위는 없다.
