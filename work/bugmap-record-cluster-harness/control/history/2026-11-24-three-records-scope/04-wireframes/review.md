# 기록 3 마커 선택 와이어프레임 검수

로그인 후 기존 발견 지도에서 기록 3을 누른 390×844 상태 한 장을 검토했다. 패널에서는 제목과 닫기, 세 기록의 사진·이름·발견일 순으로 확인할 수 있다. 제목의 3건은 선택한 마커의 공개 기록 수를 뜻한다. [PNG](captures/main-map/cluster-selected.png) · [SVG](main-map/cluster-selected.svg) · [흐름](../03-structure/flows.mmd)

## 배치 결정

- 기존 지도 캡처와 와이어프레임을 열어 대조했다. 진입 지도 `41:81`의 카메라와 마커 `41:394`의 기준 중심 (300, 333)을 선택 상태에도 사용했다. 저충실도에서 테두리로 선택을 구분하고, 기록 마커와 내 위치는 각각 글자가 있는 배지와 점으로 표시했다. 후속 시안에서는 기존 다크 팔레트의 기록 강조 역할을 사용하고 공식 지도 로고와 스타일을 재사용한다. [원본 지도 PNG](../../bugmap-main-map-harness/06-figma/captures/main-map-default.png)
- 사용자가 제시한 Kyro의 면적 비율을 참고해 패널을 y=396부터 화면 바닥까지 448px, 화면 높이의 53.1%로 확대했다. 위쪽 두 모서리의 반경은 32px다. 제목과 닫기 아래에 높이 104px인 기록 행 세 개를 둔다. 마지막 행은 y=796에서 끝나고 하단 안전 영역은 y=810부터 34px다. [Kyro 참고 화면](../02-research/captures/kyroMakerClick.png)
- Mapbox 로고를 지도 왼쪽, 출처 버튼을 오른쪽에 배치했다. 기록 7에서 다른 묶음을 선택할 수 있다. 패널 밑의 기록 5와 GPS·기록 작성은 선택 상태에서 숨긴다. 패널을 닫으면 같은 카메라의 기본 지도로 돌아가고 검색·탭, GPS·기록 작성 버튼이 복원된다.
- 예시 기록의 날짜와 공개 좌표는 시연용이다. 사진 자리 세 개를 각각 80×80px로 확대했다. 후속 시각 명세에서 제목은 24px, 곤충 이름은 18px, 발견 날짜는 14px다. CLI 캡처의 문구는 14px로 렌더링된다. 후속 자산 선정 시 저장소의 사진 출처와 사용 조건을 확인한다.

## 390×844 검수 결과

정식 저장소의 하네스 `check`에서 PRD·리서치·구조의 통과를 확인했다. 승인된 구조의 제작 상태, JSON 및 하네스 출력은 `main-map/cluster-selected` 한 장으로 일치한다. 스테이징에서 공식 `wireframe` 명령을 임시 Chrome 프로필로 실행해 SVG와 PNG를 생성했다. [생성 리포트](wireframes-report.json)

생성 PNG를 직접 열어 강조 마커와 내 위치의 구분, 기록 7, 패널 위 좌우의 Mapbox·ⓘ, 제목과 닫기, 큰 사진 자리와 이름·발견일이 포함된 세 행을 확인했다. 패널 위쪽 모서리는 둥글고 하단은 화면 바닥에 닿는다. 마지막 행과 하단 안전 영역 사이에는 14px가 남고 홈 인디케이터는 안전 영역 안에 보인다.

| 대상 | x, y | 범위 |
| --- | --- | --- |
| 지도 출처 | 338, 344 | 44×44px |
| 닫기 | 326, 408 | 48×48px |
| 첫째 행 | 16, 468 | 358×104px |
| 둘째 행 | 16, 580 | 358×104px |
| 셋째 행 | 16, 692 | 358×104px |

JSON 좌표로 버튼 7개의 44×44px 이상 크기, 상호 비겹침과 상·하 안전 영역을 확인했다. 출처 버튼과 기록 3의 강조 외곽 사이에는 가로 2px 간격이 있다. 패널의 읽기 순서는 제목과 닫기, 그 아래 세 행이다.

좁은 화면이나 큰 글자에서 이름을 줄바꿈하고 행 높이를 내용에 맞춰 늘린다. 목록이 패널에 넘치면 목록만 세로로 스크롤하며 제목·닫기와 지도 위 선택 마커·출처는 계속 보이게 한다. 스크롤 끝에는 하단 안전 영역을 반영해 마지막 행을 읽고 누를 수 있게 한다. 실제 스크롤과 접근성 포커스는 구현에서 검증한다.

## 요구사항별 후속 확인

| 요구사항 | 확인한 증거와 후속 단계 |
| --- | --- |
| CLUSTER-01 | 390×844 캡처에서 강조 마커, 지도 영역과 대체 패널이 보인다. Figma에서 기존 `41:394` 탭 후 선택 화면으로 전환되는지 조작한다. |
| CLUSTER-02 | 제목에 3건, 세 행에 썸네일 자리, 곤충 이름과 발견일을 확인했다. 이름 미확인 표기를 확인했다. 실제 사진과 최종 글꼴에서 긴 한글 이름과 큰 글자에서 날짜가 잘리는지 확인한다. 기준 크기의 Figma 캡처에서는 세 행이 보이는지 확인하고, 목록 스크롤은 구현에서 검증한다. |
| CLUSTER-03 | 세 행의 터치 영역과 별도 기록 ID 목적지를 기하 검수와 구조 명세에서 확인했다. 같은 공개 좌표 그룹인 첫째·둘째의 상세 목적지는 별개다. 사진 전체와 메모의 실제 상세 진입은 앱에서 확인한다. |
| CLUSTER-04 | 닫기 영역과 원본 및 선택 지도 사이의 카메라 복귀 규칙을 확인했다. Figma에서 닫았을 때 같은 카메라와 하단 검색·탭, GPS·기록 작성 버튼이 복원되는지 조작한다. 다른 묶음으로 바꾸는 동작은 강조·건수·목록을 함께 갱신하는 구조 명세를 따른다. |
| CLUSTER-05 | 출처 버튼의 44×44 영역과 로고 자리의 가시성을 확인했다. Figma에서 원본 공식 로고와 버튼 영역을 확인하고 기존 출처 연결이 있으면 열기와 닫기를 조작한다. 연결이 없으면 열기는 Mapbox SDK를 적용한 앱에서 검증한다. |
| CLUSTER-06 | 제작 상태 한 장의 JSON·SVG·PNG를 확인했다. Figma 단계에서 Page 1의 새 편집 가능 프레임, 진입·복귀 및 원본 레이어와 기존 인터랙션을 대조한다. |

시각 검수 범위는 로컬 390×844 정적 캡처다. 실제 지도·공식 로고와 실기기 안전 영역, Figma 연결, 원본 노드 및 인터랙션, SDK 출처 열기, 지도 조작, 실제 접근성 트리·스크롤 및 제품의 로딩·빈 결과·오류 복구는 이후 검증 범위다.
