# 기록 묶음 선택 리서치 제안

아래는 승인 PRD를 유지하며 구조와 와이어프레임에서 검토할 제안이다. 화면에서 본 내용은 [리서치 관찰](findings.md)에 기록했다. 각 요구사항의 확인 기준은 [요구사항 표](../01-prd/requirements.csv)를 따른다.

| 승인 요구사항 | 관찰 또는 결정 근거 | 다음 설계에 적용할 제안 |
| --- | --- | --- |
| `CLUSTER-01` 선택 마커와 패널 | Kyro는 지도 선택 대상과 패널 제목을 한 화면에 둔다. BugMap의 진입 마커는 가운데 오른쪽에 있다. | 같은 카메라와 지형 기준점에서 `기록 3` 필의 윤곽과 명도 대비를 높인다. 현재 위치의 하늘색과 혼동하지 않도록 기존 다크 팔레트의 기록 강조 역할을 사용한다. 하단 검색·탭이 차지한 자리를 제목과 목록으로 바꾸고, 패널 상단을 세 행에 필요한 높이까지만 올려 지도와 마커를 남긴다. |
| `CLUSTER-02` 제목과 세 행 | Kyro는 목록 전에 여러 요약 지표를 쓴다. 승인 PRD에서는 로그인한 사용자가 첫 화면에서 무엇이 언제 발견되었는지 확인해야 한다. | 첫 줄 왼쪽에 `이 주변 관찰 기록 3건`을 둔다. 세 행에는 왼쪽에 같은 크기의 사진 썸네일, 오른쪽에 곤충 이름과 실제 발견 날짜를 둔다. 제목의 수는 선택된 묶음에 속한 공개 기록에 맞춘다. 이름 미확인은 `이름 모름`으로 표시한다. 긴 이름이 두 줄이어도 날짜와 셋째 행이 보이는지 390×844에서 확인한다. |
| `CLUSTER-03` 개별 상세 진입 | 공개 좌표가 같아도 서로 다른 상세를 열어야 한다는 승인 요구사항이다. 지도 PNG로는 기록별 ID나 상세 내용을 확인할 수 없다. | 행 전체에 최소 44×44 터치 영역을 부여한다. 각 행에 별도의 예시 기록 ID를 지정하고 ID별 전체 사진과 메모로 이어지는 목적지를 구조에 명시한다. 동일 공개 좌표인 두 기록을 서로 다른 행과 상세에 대응시키는 예시로 검토한다. |
| `CLUSTER-04` 닫기와 선택 갱신 | Kyro에서는 패널 우측 상단에 X가 보인다. 기존 BugMap 지도에는 `기록 3` 외에 두 묶음이 더 보인다. | 제목 줄 오른쪽에 최소 44×44 닫기 영역을 둔다. 닫기는 같은 카메라의 기존 지도로 돌아가며 선택 강조를 풀고 검색·탭을 복원한다. 다른 묶음 선택 시 강조·제목 건수·목록이 같은 선택을 기준으로 함께 바뀌는 규칙을 구조에 적는다. |
| `CLUSTER-05` 지도 출처 | 기존 지도는 로고와 `ⓘ`를 지도 하단 좌우에 분리한다. Mapbox 가이드는 정보 버튼을 지도 안에서 재배치할 수 있다고 설명한다. | 공식 로고의 형태와 색을 유지한다. 로고와 정보 버튼의 좌우 관계를 우선 유지하되, 패널 높이에 맞춰 버튼의 최소 44×44 터치 영역 전체가 보이는 지도 안에 놓이도록 조정한다. 목록, 선택 마커, GPS·기록 작성과의 가려짐·겹침을 검사한다. 기존 출처 인터랙션이 있으면 선택 시안에서 재사용해 실제로 눌러 확인한다. 기존 연결이 없으면 시안의 위치·터치 영역을 확인하고 출처 열기는 앱 검증으로 기록한다. |
| `CLUSTER-06` 기존 지도와 편집 가능한 프레임 | 기존 지도 캡처와 승인 설정은 Page 1의 기본 지도 `41:81`을 기준으로 한다. | 같은 배치와 구성 요소를 기준으로 편집 가능한 상태 프레임 한 장을 준비한다. 원본 프로토타입 편집 범위는 `41:394`의 진입 동작이다. Figma 단계에서 Cursor 브리지로 대상과 기존 인터랙션을 조회한 뒤, 해당 진입과 선택 화면의 닫기를 연결할 수 있는지 확인한다. 원본의 나머지 연결과 레이어는 작업 전후 비교 대상으로 둔다. |

## 와이어프레임에서 판단할 항목

- **패널 높이와 지도 조작부.** 제목과 닫기, 세 행, 안전 영역부터 배치한다. 그 높이에서 선택 마커, Mapbox 로고, 출처 버튼과 그 터치 영역을 확인한다. GPS·기록 작성은 현재 지도와의 연속성을 위해 겹침 없이 유지할 수 있는지 먼저 비교한다. 공간이 부족하면 선택 중 이 두 동작을 잠시 숨기는 안도 검토한다. 어느 경우든 닫으면 기존 배치로 복귀한다. `CLUSTER-01`, `CLUSTER-02`, `CLUSTER-04`, `CLUSTER-05`.
- **예시 기록과 긴 이름.** 세 가지 별도 기록의 썸네일·이름·실제 발견 날짜를 사용할 수 있도록 자산 출처와 표시 순서를 후속 설계에서 정한다. 발견일 내림차순을 예시 순서로 검토하되 제품 정렬 정책은 기존 승인 범위 안에서 확정된 항목을 따른다. 긴 한글 이름, `이름 모름`, 동일한 공개 좌표를 각각 검수할 수 있게 예시를 구성한다. `CLUSTER-02`, `CLUSTER-03`.
- **동작과 정적 검수.** 390×844 캡처에서 세 행·긴 이름·지도·강조 마커·로고·정보 버튼을 확인한다. 노드에서 닫기·행·출처의 실제 터치 영역을 확인하고, 프로토타입에서 `기록 3 → 선택 패널 → 닫기 → 같은 지도`를 조작한다. 기존 출처 연결의 존재와 작동 여부는 Figma 단계의 확인 사항이다. 다른 묶음의 갱신 및 상세 목적지는 구조 명세에 기록한다. `CLUSTER-01`~`CLUSTER-06`.

승인 범위 변경이 필요한 리서치 발견은 없다. 지도와 출처 SDK의 실제 동작, 검색·GPS·작성 버튼의 원본 연결, 시연 자산 사용 조건은 후속 확인 사항이다.
