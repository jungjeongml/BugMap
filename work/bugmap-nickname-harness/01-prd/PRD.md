# BugMap 신규 가입 닉네임 설정

신규 소셜 가입을 마친 사용자가 발견 지도에 들어가기 전에 서비스에서 사용할 닉네임을 설정한다. BugMap 닉네임을 저장한 사용자는 온보딩을 반복하지 않는다. 소셜 계정에서 받은 표시 이름만 있는 경우에는 이 단계가 완료된 것으로 처리하지 않는다. 저장된 닉네임은 이후 공개 기록에서 작성자 이름으로 쓰이는 것을 전제로 안내한다.

## 화면 범위

한국어 모바일 화면 3개를 [BugMapHarness 파일의 Page 1](https://www.figma.com/design/Dan8qlRM20XPkk7Mtd5riw/BugMapHarness?node-id=0-1)에 편집 가능한 프레임으로 제작한다. 390 × 844 px를 기본으로 하고 360 × 800 px와 시스템 키보드가 열린 배치를 검수한다. Cursor MCP Plugin과 Cursor Talk to Figma 브리지에서 파일·페이지·대상 프레임을 확인한다.

| 상태 | 시안의 표시와 다음 동작 |
|---|---|
| 첫 입력 | 한 줄 닉네임 입력란과 공개 이름 안내를 표시한다. 예시 문구는 힌트로 표시하며 입력값은 비어 있다. ‘시작하기’는 비활성이다. 키보드가 열린 배치를 시연한다. |
| 저장 가능 | 예시 ‘숲길관찰자’를 입력한 상태다. ‘시작하기’는 활성이다. 저장에 성공하면 기존 발견 지도로 이동한다. |
| 입력 오류 | 예시 ‘숲’을 지우지 않고 ‘닉네임을 2자 이상 입력해 주세요’라고 안내한다. ‘시작하기’는 비활성이다. 오류는 문구와 입력란 스타일로 표시하며 사용자가 즉시 수정할 수 있다. |

## 흐름과 시안용 규칙

- 신규 가입 완료 → 닉네임 설정 → 닉네임 저장 성공 → [기존 발견 지도](https://www.figma.com/design/Dan8qlRM20XPkk7Mtd5riw/BugMapHarness?node-id=41-81). 닉네임이 아직 저장되지 않았으면 앱을 닫았다가 다시 열거나 나갔다가 들어와도 닉네임 설정으로 돌아온다.
- 시안은 앞뒤 공백을 제외한 2~12자를 유효한 길이로 가정한다. 빈 초기 상태에서는 오류를 표시하지 않는다. 사용자가 비어 있지 않은 잘못된 값을 입력하고 키보드 완료를 누르거나 입력칸을 벗어나면 안내한다. 수정 중에는 오류 문구와 버튼 상태를 실제 조건에 맞춰 갱신한다. 상태 명세에서 빈 값·공백만 입력·1자·2자·12자·13자를 구분한다. 한글 입력 중에는 조합이 끝난 값을 기준으로 판정하고, 키보드 완료 시 안내를 표시할 조건을 명시한다. 허용 문자·중복 및 변경 정책은 제품 구현 전에 결정한다.
- 저장 중에는 중복 요청을 막는다. 저장 실패 시 입력값을 유지하고 재시도할 수 있게 한다. 이 동작은 상태 명세에 기록한다. 세 번째 프레임은 사용자가 바로 고칠 수 있는 길이 오류를 보여준다.
- 시안은 기존 05 로그인과 발견 지도의 다크 톤 및 연두색 강조를 이어간다. Kyro 첨부는 입력 한 칸과 다음 행동이 한눈에 들어오는 구성의 참고로 사용한다. 초기 한 화면에서 설정하는 방식과 입력·확인을 두 화면으로 나누는 방식을 검토했다. 이 작업에서는 한 화면에서 입력을 확인하고 바로 시작할 수 있도록 같은 레이아웃에서 상태만 바꾸는 방식을 제안한다.
- 제목·보조 문구·입력란·오류·버튼의 순서가 안정적으로 유지되어야 한다. 모든 활성 조작 영역은 최소 44 × 44 px이며 키보드가 열려도 입력, 상태 안내와 주요 행동에 접근할 수 있어야 한다.
- Figma에 세 상태를 독립 프레임으로 표시한다. 저장 가능 프레임의 ‘시작하기’에서 기존 지도로 이동하는 연결로 저장 성공을 시연한다. 실제 텍스트 입력·서버 중복 검사·저장 동작의 구현은 별도다. 기존 로그인·지도 프레임은 연결 참고 및 목적지로 사용하며 이번 제작에서 기존 인증 경로를 바꾸지 않는다.
