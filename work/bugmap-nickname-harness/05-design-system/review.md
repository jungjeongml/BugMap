## 디자인 선택

- 바탕 `#101C16`, 강조 `#C5EE79`, 입력 면 `#1C2C23`과 버튼 안 글자 `#202E13`을 BugMap 다크 흐름에서 가져왔다. 유효 상태의 입력 테두리 `#6D8677`과 비활성 글자 `#8FA496`도 이전 기록 작성의 조작 영역 색을 사용했다. 오류 전용 코랄 `#FFA99B`는 경계와 오류 문구에 적용했다.
- Pretendard Medium/Bold를 사용한다. 제목은 28/36 px, 보조 문구는 15/22 px, 입력값은 16/24 px다. 화면 위에는 기존 BugMap 로고와 직접 구성한 지형선·관찰 표식을 담은 가로 영역을 둔다.
- 버튼 높이는 48 px, 입력란 높이는 52 px다. 390 × 844에서 키보드 영역은 y=540, 360 × 800에서 y=504부터 시작하며 두 경우 모두 시작하기 버튼과 20 px 간격을 둔다. 키보드 키와 시스템 표시는 정적 시연용으로, 앱에서는 운영체제 UI를 사용한다.

## 검수 근거

해시 `ebce27611649e79a87153b9de2040904822a0c19ed1d40070f564798ae174d36`인 승인 와이어프레임 JSON을 [좌표 원본](layout.json)에 반영했다. 하네스 `design-md`로 [토큰·컴포넌트 문서](DESIGN.md)를 생성했다. 브라우저에서 여섯 장을 캡처하고 모두 직접 열어 글자 잘림이나 겹침, 도움말·오류 노출, 버튼 구분을 확인했다. [렌더 검수 기록](render-report.json)

- 여섯 화면의 브라우저 실측 좌표가 승인 배치와 일치하고, 입력·버튼 크기와 키보드 위 간격을 만족한다. Pretendard 두 가중치와 로고 로드, 오류의 입력 연계, 비활성 버튼 속성을 확인했다.
- 코랄 오류 문구와 화면 배경의 대비는 9.50:1이다. 활성 버튼 글자와 연두색 바탕은 10.86:1, 비활성 문구와 비활성 바탕은 5.02:1이다. 중립 입력 테두리와 입력 배경은 3.71:1이다.
- Figma의 조작 가능한 노드, 저장 성공 시 기존 발견 지도로 가는 프로토타입, 실제 키보드·접근성 알림과 사용자 저장은 이 단계에서 조작하지 않았다. 오류가 드러난 상태에서 한글 조합이 끝난 값을 다시 판정하는 규칙은 승인된 상태표를 따른다.

## 후속 Figma 제작

세 편집 가능한 전체 프레임은 390 × 844 캡처에 대응한다. [좌표와 상태](layout.json), [색·문자 토큰](tokens.json), [정확한 표시 문구](copy.json) 및 [미리보기 소스](previews/nickname.css)를 기준으로 구성한다. `preview.svg`는 브라우저로 보는 시각 참고이며 편집 가능한 Figma 노드의 소스는 아니다. 360 × 800은 추가 Figma 프레임이 아닌 작은 화면 검증 기준이다. 기존 발견 지도 41:81은 저장 가능 상태의 프로토타입 목적지로 사용한다.
