# 닉네임 설정 설계에 적용할 제안

[승인 PRD](../01-prd/PRD.md)와 [수용 기준](../01-prd/requirements.csv)에 맞춘 구조·와이어프레임 제안이다. 관찰 근거는 [리서치 기록](findings.md)에 있다.

| 요구사항 | 적용안 |
| --- | --- |
| NICK-01 · 신규 가입 흐름 | 소셜 가입 완료 뒤 BugMap 닉네임 저장 여부에 따라 분기한다. 저장 전 재진입은 설정으로, 이미 저장한 계정은 메인 지도로 이어진다. 소셜 표시 이름 보유는 별도 조건이다. |
| NICK-02 · 첫 입력 | 설명 바로 아래에 지속되는 ‘닉네임’ 레이블과 한 줄 입력을 둔다. 아래에는 길이 안내 자리를 확보한다. 빈 상태는 오류 없이 보여주고 버튼은 비활성으로 둔다. |
| NICK-03 · 저장 가능 | 예시 ‘숲길관찰자’에 활성 CTA를 사용한다. 화면의 같은 위치에서 버튼 강조가 바뀌고 성공 시 기존 발견 지도 `41:81`로 이어진다. |
| NICK-04 · 입력 오류 | 같은 필드에서 ‘숲’을 보존하고 그 아래에 ‘닉네임을 2자 이상 입력해 주세요’를 표시한다. 공백 정리, 0·1·2·12·13자, 한글 조합 종료 전후와 키보드 완료 후 복구를 상태표에 적는다. 오류 표시 예약 영역을 두어 주요 버튼의 위치가 크게 바뀌지 않게 한다. |
| NICK-05 · 작은 화면과 키보드 | 글자와 조작 영역을 유지한 채 장식부터 줄인다. 390 × 844와 360 × 800에서 키보드가 차지하는 공간을 표시하고 입력, 안내, 주요 행동이 가려지는지 본다. 시스템 키보드 영역과 제품 UI를 구분한다. |
| NICK-06 · Figma 대상 | Page 1에 독립된 세 상태 프레임을 만들고 기존 로그인과 지도를 배치 전후 대조한다. ‘시작하기’에서 지도로 이동하는 성공 시연을 검수 대상으로 남긴다. |
| NICK-07 · 저장 복구 | 저장 대기 중 중복 제출을 막고, 실패 시 입력과 폼을 유지한 채 재시도한다. 이 두 상태는 구조 명세에 기록한다. |

기존 다크 그린과 연두색 강조가 시각 방향의 기준이다. 공개 작성자 이름 안내를 앞에 두고 키보드 높이가 달라져도 할 일을 읽고 수행할 수 있게 구성한다. 실제 서버 저장, 허용 문자·중복·변경 정책, 시스템 키보드와 접근성 조작은 Figma 시안과 별도로 확인할 사항이다.
