# 닉네임 설정 리서치 관찰

## Kyro 신규 가입 닉네임 설정

- **직접 본 것.** 검은 배경 상단에 도시 모형이 크고 중앙 아래에 제목과 지도에 표시될 이름이라는 안내가 있다. 한 줄 입력은 값을 비운 채 삽입점만 보인다. 회색 ‘다음’ 버튼은 한국어 시스템 키보드 바로 위에 온전히 보인다. 키보드 오른쪽 아래에는 파란 완료 키가 있다.
- **적용.** 이름을 먼저 정하는 이유를 짧게 말하고, 입력 한 칸과 주요 행동을 같은 화면에 둔다. 빈 첫 화면은 비활성 CTA를 보여준다. 키보드 위에 입력과 안내, ‘시작하기’를 함께 보이는 배치를 검수한다. NICK-02, NICK-05.
- **피할 점.** 도시 모형의 시각 자산과 큰 상단 면적은 가져오지 않는다. 작은 화면에서 오류 안내와 주요 행동을 먼저 배치한다. 입력 값과 관계없이 닉네임이라는 목적을 알 수 있도록 필드 위 레이블을 둔다. Kyro 캡처에서 보이는 입력란에는 별도 필드 레이블이 없으므로 입력 힌트만으로 그 역할을 맡기지 않는다.
- **해석과 미검증.** 빈 입력 상태의 한 장이다. 포커스 진입 방법, 완료 키 동작, 유효성이나 저장 실패와 접근성은 이미지에서 확인하지 못했다. [첨부](captures/kyroNickname.png)

## BugMapHarness 첫 로그인

- **직접 본 것.** 어두운 녹색 지도 배경 위에 연두색 BugMap 로고와 강조 제목이 보인다. 제목과 목적 문장은 버튼보다 앞에 온다. 제공자별 버튼 세 개는 같은 폭의 둥근 행으로 보이며 하단에는 약관 한 줄이 있다.
- **적용.** 로고, 어두운 녹색 톤, 연두색 강조, 여백 리듬을 가입 다음 화면으로 연결한다. 닉네임 입력은 자체 제품 UI라 제공자 색과 무관한 BugMap 공통 버튼 및 입력 토큰을 쓴다. NICK-02, NICK-05.
- **피할 점.** 로그인처럼 큰 지도 배경과 여러 버튼을 배치하면 단일 입력 흐름의 여백이 줄어든다. 시안용 로그인 캡처의 네이버 버튼은 현재 로그인 명세의 제공자 기준으로 사용하지 않는다.
- **해석과 미검증.** 기존 시안 PNG를 읽었다. 소셜 가입과 다음 화면 전환을 직접 조작하지 않았다. [로그인 PNG](../../bugmap-login-map-harness/06-figma/captures/login-default.png) · [현재 로그인 명세](../../../docs/screens/login.md)

## BugMapHarness 발견 지도

- **직접 본 것.** 지도 하단의 다크 패널 위에서 주요 기록 행동이 밝은 연두색 버튼으로 보이고, 일반 검색과 탐색은 어두운 면에 밝은 글자로 구분된다. 하단 안전 영역 위에는 네 탐색 탭이 있다.
- **적용.** 연두색 표면과 진한 글자의 우선 행동 방식을 유효한 ‘시작하기’ 상태에 적용한다. 저장 성공 시 기존 발견 지도 프레임을 목적지로 두어 시연한다. NICK-03, NICK-06.
- **피할 점.** 탐색 탭과 지도 검색은 가입 설정 화면에 옮기지 않는다. 당시 지도 PNG의 상호작용 여부를 정적 자료에서 추론하지 않는다.
- **해석과 미검증.** PNG의 배치와 역할만 확인했다. 지도 전환과 계정 분기 및 실제 저장은 후속 검증이다. [지도 PNG](../../bugmap-main-map-harness/06-figma/captures/main-map-default.png)

## Apple HIG Text fields

- **직접 본 것.** 캡처의 텍스트 필드 안내에서 이름처럼 짧은 정보에 한 줄 입력을 쓰고, 힌트가 사라진 뒤에도 필드를 식별할 수 있도록 별도 레이블을 고려하라고 설명한다. 별도로 읽은 문서 본문은 입력 맥락에 따라 검증 시점을 정하고 내용에 맞는 키보드 유형을 사용하라고 권한다.
- **적용.** ‘닉네임’ 레이블을 유지하고, 힌트에는 입력의 예를 든다. 입력 완료나 포커스 이동 후 표시하는 구체적인 길이 오류와 한국어 입력 조합 중의 상태를 구조 명세에 기록한다. NICK-02, NICK-04, NICK-05.
- **피할 점.** Apple 예시 스타일과 문구는 제품 토큰이나 카피로 사용하지 않는다. 즉시 검증 사례를 글자 조합 중에 오류를 띄워야 한다는 근거로 적용하지 않는다.
- **해석과 미검증.** 공개 가이드와 Chromium 캡처를 읽었다. iOS·Android 시스템 키보드 동작, 키보드 높이, 실제 초점 이동과 읽어 주기는 별도 검증 항목이다. [공식 가이드](https://developer.apple.com/design/human-interface-guidelines/text-fields) · [PNG](captures/apple-hig-text-fields.png)
