# 화면 구조에 적용할 제안

| 요구사항 | 관찰 근거 | 적용 제안 | 다음 확인 |
| --- | --- | --- | --- |
| HOME-01·07 | 두 참고 화면에서 지도는 배경 전체에 이어지고 패널은 하단에 모인다. | 390×844의 기본 화면 한 장에서 지도를 전면에 둔다. 마커와 조작 요소를 지도 배경과 구분한다. | 와이어프레임에서 손잡이부터 시스템 하단 여백까지의 높이와 지도에 남는 면적을 확인한다. |
| HOME-02 | 두 화면 모두 패널 상단 중앙에 손잡이가 있다. | 접힌 패널을 첫 상태로 한다. 위로 드래그하면 ‘내 주변 발견’이 열린다는 동작을 구조 문서에 기록한다. | 이번 시안에 필요한 화면은 접힌 상태 한 장이다. |
| HOME-03·04 | Kyro의 입력이 탭 위에 있고, 이전 BugMap 검색 문구에는 곤충과 지역이 함께 나온다. | 손잡이 → 돋보기와 ‘곤충 이름 또는 지역 검색’ → 지도·커뮤니티·채팅·마이 순서로 둔다. 지도만 선택 상태로 표시하고 검색·각 탭의 터치 영역에 최소 44×44px를 배정한다. | 네 탭의 동일한 가로 배분, 힌트 한 줄, 하단 안전 영역을 점검한다. |
| HOME-05·06 | 두 화면에서 위치 버튼과 주요 동작이 패널 바로 위 좌우에 분리된다. | 왼쪽에 현재 위치로 이동하는 버튼, 오른쪽에 ‘발견/채집 기록하기’를 두고 각각 44×44px 이상을 확보한다. | 기록 레이블이 한 줄로 들어가고 조작 영역이 패널·출처 버튼과 겹치지 않는지 확인한다. |
| HOME-07 | 이전 BugMap에서 현재 위치점과 공개 기록 배지가 모양으로 구분된다. Mapbox 공식 문서에는 지도 위 출처 표시 기준이 있다. | 기본 다크 지도에서 시연용 기록 수 배지와 작은 현재 위치점을 형태와 시각 위계로 구분한다. 필터 미적용 상태에서는 주변 반경 경계를 숨긴다. 지도 위에서 Mapbox 공식 로고와 SDK 정보 버튼이 읽히고 조작될 공간을 남긴다. | 지명·관찰 기록·현재 위치는 예시 데이터로 관리하고 출처 요소를 후속 Figma 검수에 포함한다. |
| HOME-08 | 승인 PRD는 기존 두 프레임을 검수 대상으로 지정한다. | 결과 프레임에 대한 실제 캡처를 받고 Figma 대상 노드 `7:2`, `19:2`를 편집 전후 대조한다. | 리서치 이미지와 실제 결과 캡처의 출처를 구분한다. |

두 캡처는 화면 구성과 시각 위계의 근거다. 손가락 도달 범위와 드래그·GPS·검색·탭 동작은 검증하지 않았다. 승인 범위를 바꾸는 제안은 없다.
