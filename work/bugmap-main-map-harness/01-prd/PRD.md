# BugMapHaness 로그인 후 메인 / 발견 지도

주변에서 어떤 곤충이 발견됐는지 찾는 사용자는 기록이 여러 게시글에 흩어져 있으면 장소와 종을 함께 확인하기 어렵다. 현장에서 곤충을 발견한 사용자에게는 바로 기록을 시작할 진입점이 필요하다. 로그인 직후 지도 탭에서 공개 기록을 보고, 곤충·지역 검색과 새 발견 기록을 한 화면에서 시작할 수 있게 한다.

## 제작 범위

- [BugMapHaness Page 1](https://www.figma.com/design/Dan8qlRM20XPkk7Mtd5riw/BugMapHaness?node-id=0-1)에 한국어 모바일 기본 프레임 `main-map/default` 한 장을 추가한다. 검수 기준은 390×844다.
- 화면 전체에 다크 지도를 깔고 공개 발견 기록의 예시 마커와 현재 위치 표시를 시각적으로 구분한다. 위치 확인과 반경 필터는 별도 개념이다. 반경이 적용되지 않은 기본 화면에서 반경 경계는 숨긴다.
- 접힌 하단 패널에 위로 끌 수 있는 손잡이, 곤충·지역을 함께 찾는 검색창, `지도 / 커뮤니티 / 채팅 / 마이` 네 탭을 배치한다. 지도 탭이 선택된 상태로 시작한다. 검색 힌트 제안은 ‘곤충 이름 또는 지역 검색’이다.
- 패널 위에 GPS 단축 버튼과 발견 기록 버튼을 서로 독립된 조작부로 배치한다. GPS는 현재 위치로 지도를 이동하는 진입점이며, 발견 기록은 기존 기록 작성 흐름의 진입점이다. CTA 문구는 기존 화면 명세의 ‘발견/채집 기록하기’를 적용한다.
- 기본 화면은 손잡이와 동작 명세로 확장 제스처를 전달한다. 위로 드래그하면 기존 명세의 ‘내 주변 발견’이 열리는 흐름이다. 확장 화면, 검색 결과, 다른 탭 화면, 기록 작성 화면, 권한 오류 화면과 실제 GPS·지도·검색 동작은 이후 범위다.

## 리서치 가정과 미결정

- 지도 위 GPS·기록 버튼과 하단 검색·탭 배치가 화면을 탐색하기 쉬울 것이라는 가정을 Kyro 첨부와 기존 BugMap 메인 지도에서 대조한다. 한 화면에서 지도 조작과 하단 조작을 구분할 수 있는지, 지도에 남는 면적이 충분한지 검토한다.
- PRD 단계에서 추가로 결정해야 하는 제품 요구사항은 없다. 검색 힌트와 패널의 치수는 와이어프레임에서 검토한다. 확장 화면의 콘텐츠와 레이아웃은 후속 디자인에서 정한다.

## 디자인 및 검수

첨부 [Kyro 화면](../../../example/kyroMain.png)의 지도 중심 레이아웃과 떠 있는 지도 조작부, 하단 검색·탭 구조를 참고한다. 시각 기준은 [BugMap 다크 팔레트](../../../docs/DESIGN.md#지도-중심-다크-팔레트)와 [메인 지도 명세](../../../docs/screens/main-map.md)를 적용한다.

지도와 시연용 위치·발견 기록은 목업 데이터다. 지도 출처를 가리지 않도록 패널과 버튼의 위치를 잡는다. [요구사항 표](requirements.csv)의 항목을 Figma 노드와 실제 캡처로 대조한다. 검색·탭·버튼은 편집 가능한 레이어로 만들고, 터치 대상은 최소 44×44로 검수한다. 지정한 두 기존 프레임은 제작 범위 밖이다.
