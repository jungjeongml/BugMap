## 첫 검토

검토한 PRD와 요구사항의 SHA-256은 각각 `06a975224d79a384a333352b87b709fe91ab02a2558f9910397c19ecc8901c9e`, `f9954de3ea54d5650b01fbb5319d3f810b31e0e9c8f6507c22416c4947fa61eb`이다. `README.md`와 `control/`의 실제 해시도 제공된 검사 결과와 일치했다. 기계 검사 상태는 `awaiting_approval`, `canApprove: true`였다.

- **중요 · 확장 제스처의 도착점 누락.** PRD 11행과 `HOME-02`는 위로 드래그했을 때 ‘확장’한다고만 적는다. 기존 화면 명세는 ‘내 주변 발견’ 목록을 연다고 정한다. 도착점이 없으면 후속 흐름과 수용 기준을 일관되게 검토하기 어렵다. 확장 화면 제작은 후속 범위로 두고 PRD와 `HOME-02`에 목록 진입을 명시한다.
- **경미 · 기록 버튼 문구 기준이 다름.** 기존 화면 명세는 ‘발견/채집 기록하기’, PRD는 ‘발견 기록하기’를 제안한다. 작성 흐름의 관찰·채집 범위가 유지된다는 결정 기록은 확인했다. 기존 문구를 적용하거나, 축약 문구를 이번 시안에서 결정할 항목으로 수용 기준에 연결한다.
- **경미 · 검토 링크 미해결.** 임시 검토 위치에서 PRD의 Kyro·디자인 기준·화면 명세 링크와 README의 재개 링크가 열리지 않았다. 승인용 위치에서 네 링크를 확인한다.

**판정 `needs_revision`**
