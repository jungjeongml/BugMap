# 구조·와이어프레임 적용 제안

| 관찰 근거 | 권장안과 수용 기준 |
| --- | --- |
| 현재 지도에는 명확한 작성 버튼과 다크 탐색 영역이 있다. 기존 작성 캡처는 별도 화면이다. | 지도 41:81의 버튼 41:443에서 작성 화면을 열고 뒤로 가면 같은 지도로 복귀하도록 구조를 잡는다. 미저장 입력이 있을 때 이탈 확인을 상태표로 정의한다. 작성 중에는 기존 지도 탭을 숨기고 현행 다크 기준을 이어받는다. ENTRY-01, ENTRY-07. |
| BugMap 기존 폼은 촬영과 첨부를 별도로 안내한다. iNaturalist 예시는 개별 사진에 썸네일을 둔다. | 위쪽 사진 영역에 ‘촬영하기’·‘사진 첨부’·합산 장수를 배치한다. 초기는 `0/3장`, 가득 찬 상태는 `3/3장`과 3개 썸네일, 추가 비활성 및 삭제를 제공한다. 한 장부터 사진 조건을 충족한다. 3장 초과 안내, 삭제 뒤 재추가, 앱 권한 실패 시 다른 사진 경로, 업로드 실패·재시도는 상태표로 검토한다. 개별 삭제에는 44×44px 이상의 영역을 마련한다. ENTRY-02, ENTRY-07. |
| 기존 폼의 곤충 이름·유형 조작이 사진 다음에 있다. | 이름 입력 또는 ‘이름 모름’과 단일 선택 ‘관찰’·‘채집’을 같은 섹션에서 구분한다. 입력 완료 상태에 한 유형만 선택된 모양을 표시한다. ENTRY-03. |
| 기존 폼에 지도 미리보기·장소명·변경 진입점이 있고, iNaturalist Evidence 예시에서 장소명을 볼 수 있다. | 위치 입력은 필수 ‘발견 위치’ 한 항목으로 구성한다. 위치 요약, ‘현재 위치 사용’, 지도에서 확인·변경하는 진입점을 제공한다. 위치 권한 거부나 GPS 실패 시 지도에서 직접 선택할 수 있는 경로를 상태표에서 확인한다. 새 기록은 발견 위치를 바탕으로 대략적인 공개 좌표를 자동 생성하는 안으로 진행한다. 다른 사용자의 지도·조회에 공개 좌표만 제공하고 게시 사진의 EXIF 위치 정보를 제거하는지 제품 흐름에서 대조한다. 공개 위치 해상도는 후속 제품 결정으로 둔다. ENTRY-04. |
| 기존 폼은 날짜와 시간 필드를 나란히 놓고 이후 선택 메모를 표시한다. | 실제 발견 날짜와 시간에 별도 필드·편집 진입점을 둔다. 그 아래 선택형 여러 줄 메모를 놓는다. 입력 완료 예시에는 위치·날짜·시간이 모두 설정된 상태를 사용한다. ENTRY-05. |
| 기존 전체 폼 높이는 390×844의 한 화면보다 크다. | 두 대표 뷰포트의 상단과 안전 영역 위 고정 ‘작성완료’를 대조한다. 스크롤 본문에서 위치·일시·메모의 순서를 확인할 수 있는 정적 보조 증거를 마련하되 대표 Figma 프레임 수는 두 개로 유지한다. 첫 진입 저장 비활성과 유효 입력 완료 상태의 활성을 구분한다. 고정과 스크롤은 후속 Figma 플레이어에서 조작 검증한다. 저장 중 중복 막기와 실패 후 초안 유지·재시도는 승인 흐름에 포함한다. ENTRY-06, ENTRY-07. |

사진 한도는 사용자가 승인한 합산 1~3장이다. 남은 장수 표시와 비활성 처리의 구체 배치는 와이어프레임에서 검토한다. 네이티브 카메라·파일 접근·GPS·실서비스 저장은 제품 구현에서 확인한다. [승인 PRD](../01-prd/PRD.md) · [수용 기준](../01-prd/requirements.csv) · [장소 및 사진 데이터 기준](../../../docs/TDD.md)
