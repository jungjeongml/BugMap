## 기존 다크 스타일 적용

- 기존 지도 흐름의 배경 `#101C16`, 입력 표면 `#1C2C23`, 사진 추가 표면 `#26382C`, 하단 영역 `#152219`, 활성 조건의 강조색 `#C5EE79`를 재사용했다. 현재 위치 아이콘은 기존 위치색 `#82D0F0`를 사용한다. [공통 다크 기준](../../../docs/DESIGN.md#지도-중심-다크-팔레트) · [색상 원본](../../../src/theme/tokens.ts)
- 필드 경계가 입력 영역을 식별하게 하려면 주변 배경과 3:1 이상으로 구분되어야 한다. 기존 `formFieldBorder`와 입력 바탕은 1.69:1이며 `photoTileBorder`와 사진 추가 바탕은 2.08:1이다. 조작 가능한 필드와 사진 추가에는 `controlOutline #6D8677`을 적용해 각 안쪽 면 대비 3.71:1과 3.16:1을 확보했다. 기존 두 윤곽색은 비활성 컨트롤, 썸네일 테두리, 하단 구분에 사용한다. 표면과 강조색은 기존 토큰 그대로 사용한다.
- 썸네일은 114×90px 원본 영역에 342×270px 사진을 배치했다. 사진마다 44×44px 삭제 영역을 제공하고 대비를 위해 아이콘 뒤를 불투명한 다크 면으로 표시했다. 사진은 기록 예시용이며 발견 일시·장소도 시연 값이다. [사진·서체·아이콘 출처](asset-sources.md) · [자산 해시](assets-manifest.json)
- 관찰·채집은 채워진 원과 강조 윤곽으로 선택을 표시한다. 스크린 리더에 순번별 사진 삭제와 선택된 항목을 전달하도록 정의했다. [토큰 및 조작 영역](tokens.json) · [구조와 상태](../03-structure/states.csv)

## 재현과 후속 확인

저장소 루트에서 `node work/bugmap-record-entry-harness/05-design-system/build.mjs`로 SVG와 자산 해시를 생성한다. `node tools/design-harness/bin/design-harness design-md --project bugmap-record-entry-harness --force`로 명세와 생성 기록을 갱신하고, `node work/bugmap-record-entry-harness/05-design-system/render.mjs`로 Chromium 캡처와 측정 결과를 생성한다. 스테이징에서 빌드·렌더할 때 각 스크립트의 첫 인수에 원본 저장소 루트를 전달한다. [빌드 소스](build.mjs) · [측정 소스](render.mjs)

제품에서는 실제 화면 인셋과 키보드 높이로 폼 뷰포트를 갱신한다. 글자 배율이 커지면 입력 행을 높이고 메모를 줄바꿈하며 하단 동작을 안전 영역 안에서 제공한다. 실제 스크린 리더, 키보드, 기기별 안전 영역, GPS와 지도 직접 선택, 사진 권한·실패·저장은 후속 확인 범위다. 다른 사용자의 지도에 표시할 대략적인 공개 좌표의 자동 생성과 사진 EXIF 위치 정보 제거는 제품 구현에서 확인한다. 공개 위치 해상도는 제품 결정으로 남아 있다. 기존 지도 버튼에서 작성으로의 진입·복귀와 스크롤 중 하단 버튼 고정은 Figma 제작 후 플레이어에서 확인한다.
