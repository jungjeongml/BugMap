## 최초 검토 판정 · needs_revision

### 발견

- **중요 · 발견 위치와 공개 범위.** PRD 11행과 `ENTRY-04`는 위치와 공개 범위를 구분해 표시하는 데 그친다. 제품 `MAP-07`에 맞춰 등록 전에 **정확한 위치 공개**와 **대략적인 위치 공개**를 선택·변경할 수 있는 UI 진입점과 흐름을 수용 기준에 추가한다. 기본값과 대략 공개 해상도는 미결정으로 둔다.
- **중요 · 검증 방법.** `ENTRY-02`의 ‘경로를 확인’과 `ENTRY-03`의 ‘고를 수 있음’은 Figma 조작 범위를 모호하게 만든다. `0/4장`, `4/4장`, 사진 삭제 조작 영역과 입력 컨트롤은 시안·노드로 확인한다. 사진 1장으로 완료 가능, 삭제 후 재추가, 이름 모름과 유형 선택의 상태 전이는 상태표에서 확인한다. 지도 버튼 진입·뒤로 복귀와 고정 ‘작성완료’ 위로 메모까지 스크롤하는 동작은 Figma에서 직접 확인하도록 명시한다.

### 유지할 점

- 최소 1장 필수, 2~3장 권장, 최대 4장 시안 제안의 구분이 적절하다. 이번 PRD 승인 범위를 시안에 적용할 상한으로 명시하면 기존 제품 PRD·TDD의 업로드 정책 결정과 혼동을 줄일 수 있다. iNaturalist의 여러 각도·서식 환경 촬영 안내는 사진 유형에 대한 참고 근거다. [iNaturalist 촬영 가이드](https://www.inaturalist.org/pages/insects)
- 다크 모드 390×844의 두 상태는 사진 상한과 완료 버튼의 활성·비활성을 대조하기에 충분하다. 위치, 발견 날짜·시간, 여러 줄 선택 메모와 저장 실패 복구도 문서 범위에 포함되어 있다.

## 2차 검토 판정 · needs_revision

PRD와 `ENTRY-04`·`ENTRY-06`의 공개 범위 수용 기준을 보완하면 승인 검토가 가능하다. 현재 문서는 등록 전 정확·대략 공개 선택을 요구하고 기본값을 미정으로 두지만, ‘작성완료’ 활성 조건에는 유효한 공개 범위가 빠져 있다. 활성 조건에 공개 범위를 추가하고, 대략 공개 시 다른 사용자에게 공개용 좌표만 표시되는 흐름을 명시하면 MAP-07을 검수할 수 있다.

사진 최소 1장과 최대 4장 제안의 근거가 분명하다. 390×844 편집 가능 시안 두 개, Figma에서 직접 확인할 진입·복귀·스크롤, 문서로 확인할 입력·오류 복구 흐름도 범위가 명확하다.

기존 작성 화면 명세, 제품 MAP-01·02·07, 메인 지도 인계를 대조했다. 검토본 SHA-256은 PRD `4981483792325e0c2d6639e416dbd7b96c3cb621e6e031d5e8ac4c40d689189e`, 요구사항 CSV `a5c0f36c0b83c6a05a78f06b692d0440fc42d510d2a67d00a37e179899b53d98`이다. 이번 검토는 Stage 01 문서에 한정했다. Figma 조작과 캡처 검수는 후속 단계에서 필요하다.

## 3차 검토 판정 · needs_revision

- **중요 — 위치 공개.** PRD 11행과 `ENTRY-04`는 대략 공개 시 타인의 지도와 조회에 공개용 좌표만 제공하도록 규정한다. 게시 사진의 위치 메타데이터를 통해 정확한 좌표가 노출되는 경로도 수용 기준에 포함해야 한다. 제품 PRD의 MAP-07과 TDD 348·378행에 따라 촬영·첨부 사진 모두 공개 전에 EXIF 위치 정보를 제거하는 조건을 게시 흐름에 추가한다.
- **유지 — 사진 장수와 입력.** 최대 4장을 제안으로 명시했고, 1장부터 등록 가능하며 촬영·첨부 합산, 상한 도달 및 삭제 후 재추가를 정의했다. 위치·발견 날짜와 시간·선택형 여러 줄 메모·하단 작성완료도 포함한다.
- **유지 — 진입·복귀와 스크롤.** `41:443`에서 작성 화면을 열고 `41:81`로 돌아오는 동작, 스크롤로 하단 필드에 접근하면서 작성완료가 고정되는 동작을 실제 Figma 플레이어의 수용 기준으로 명시했다.

### 발견

- **중요** — 작성 PRD 10행은 선택형 메모를 요구한다. `docs/TDD.md` 146·287행에 설명 저장과 상세 조회가 정의돼 있으나, 285행의 생성 API에는 메모 요청 필드가 빠져 있다. `ENTRY-05`의 기준도 입력란 확인까지다. 생성 요청에 선택형 메모(`description`)를 명시하고 메모를 입력해 저장한 뒤 기록 상세에서 같은 값을 확인하는 수용 조건을 추가한다.

### 유지할 점

`MAP-07`, `ENTRY-04`, 작성 PRD와 생성 API 계약 모두 발견 위치 한 항목으로 등록하는 흐름을 설명한다. 위치 권한이나 GPS가 실패해도 지도에서 직접 위치를 지정할 수 있다. 대략적인 공개 좌표 자동 생성은 설계안이며 해상도는 후속 결정이다. 다크 스타일, 촬영·첨부 합산 1~3장, 발견 일시와 하단 ‘작성완료’도 요구사항에 남아 있다.

### 미검증과 재검토 조건

기존 저장소의 읽기 전용 하네스 검사는 후보 적용 전 PRD를 `passed`로 표시했다. 해당 승인 스냅샷의 PRD·수용 기준 해시는 위 후보와 다르다. 후보 반영 후 새 해시 기준으로 하네스 상태를 확인해야 한다. 이번 문서 검토에서 Figma 캡처 확인이나 프로토타입 조작은 수행하지 않았다.

### 수정 반영

기록 생성 요청에 선택 메모를 추가하고, 상세 조회에서 여러 줄 메모를 확인하는 기준을 ENTRY-05에 넣었다. 기록 상세의 좌표 범위도 작성자와 다른 사용자의 조회에 맞춰 명시했다. 이전 화면의 입력·스타일 절은 과거 시안 아래로 옮겼다.
