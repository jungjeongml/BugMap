# BugMap 첫 로그인과 Mapbox 배경 설계

2026-11-20에 사용자가 정적 Mapbox 스냅샷과 iOS·Android의 카카오·Google 로그인, iOS의 Apple 로그인을 선택했다. 약관과 개인정보처리방침은 로그인 하단의 두 밑줄 링크로 표시하기로 했다. 두 정책 문서는 게시 전이다.

## 목표와 화면

새 사용자는 한국어 로그인 화면에서 서비스가 곤충 발견을 지도에 기록하는 앱임을 이해하고, 해당 OS에서 지원하는 제공자로 가입 또는 로그인한다. 기존 사용자는 세션이 유효하면 메인 발견 지도를 연다.

- Figma는 BugMapHarness의 [05 · 첫 로그인 / 지도 배경](https://www.figma.com/design/Dan8qlRM20XPkk7Mtd5riw/BugMapHarness?node-id=19-2)을 수정 대상으로 삼는다. Cursor Talk to Figma MCP로 연결한 뒤 파일·페이지·대상 노드를 확인하고 편집 전후 캡처를 남긴다.
- 05의 다크 스타일, BugMap 로고, 두 줄 소개, 하단 소셜 버튼과 약관 영역을 기준으로 삼는다. 위에서부터 카카오, Google, iOS의 Apple을 배치한다. Android에서는 두 버튼에 맞게 레이아웃이 줄어든다. 공식 한국어 버튼 자산과 표기를 쓴다. [카카오](https://developers.kakao.com/docs/latest/ko/kakaologin/design-guide) · [Google](https://developers.google.com/identity/branding-guidelines) · [Apple](https://developer.apple.com/design/human-interface-guidelines/sign-in-with-apple/)
- 지도 배경은 [07 · 메인 / 발견 지도](https://www.figma.com/design/Dan8qlRM20XPkk7Mtd5riw/BugMapHarness?node-id=41-81)의 서울숲·성수동·한강 구도를 기준으로 한다. 지도 스타일, 기본 카메라(중심·줌·방향·기울기)와 출력 크기를 기록해 재현할 수 있게 한다. HUD·검색·탭·내 위치·계정별 기록은 로그인 배경에서 제외하고, 상하에 어두운 페이드를 적용한다. 지도 본문은 장식으로 처리하고 Mapbox 로고와 출처 고지는 가려지거나 잘리지 않는 위치에 둔다.
- 회원가입 전이나 인증 요청 중에도 화면과 정책 링크를 읽을 수 있게 한다. 지도 이미지를 불러오지 못하면 공통 다크 배경이 표시되고 버튼을 계속 사용할 수 있다. 인증 성공 후 같은 스타일의 메인 발견 지도로 진입한다. 기존 앱에 메인 지도 라우트가 없으므로 이 작업에서는 기본 Mapbox 화면 진입점까지 연결한다. 검색·기록·탭 등 전체 지도 기능은 해당 화면의 별도 구현 범위를 따른다.

## 지도 방식 비교

| 방식 | 결과 |
| --- | --- |
| **선택 · 정적 Mapbox 스냅샷** | 로그인 화면에 지도 SDK 초기화가 필요 없다. 출시 전 메인 지도와 승인된 스냅샷의 스타일·카메라를 대조한다. |
| 실시간 Mapbox | 동일 렌더러를 바로 표시할 수 있다. 로그인 단계에서 SDK와 지도 네트워크가 작동하므로 로딩·실패·출처 UI를 함께 처리해야 한다. |

스냅샷 생성 방법은 메인 지도 스타일을 확인한 뒤 정한다. Mapbox Static Images API는 Web Mercator를 지원하고 Mapbox Standard 계열에는 호환되지 않는다. 스타일 또는 투영이 호환되지 않으면 네이티브 SDK 스냅샷을 검증한다. 로고·출처와 산출물의 저장·앱 배포 조건을 확인해서 이미지 제공 방식을 정한다. Figma에는 앱과 같은 스냅샷 또는 배포용 스냅샷을 만들기 전의 승인된 임시 배경을 사용한다. [Static Images API](https://docs.mapbox.com/api/maps/static-images/) · [SDK 스냅샷 예시](https://docs.mapbox.com/ios/maps/examples/static-map-snapshot/) · [Mapbox 출처 표시](https://docs.mapbox.com/help/dive-deeper/attribution/)

## 로그인과 세션

1. 앱에서 공식 제공자 SDK 또는 시스템 인증 브라우저로 로그인한다. 인증 요청 중에는 중복 탭을 막는다. 사용자가 취소하면 같은 화면으로 돌아갈 수 있고, 네트워크·인증 오류가 나면 이유와 재시도 경로를 표시한다.
2. 앱은 제공자 자격 증명을 BugMap 인증 API로 교환한다. 현재 저장소에는 Expo 로그인 UI가 있으므로 실제 인증에는 서버와 테스트 제공자 등록이 필요하다. 기존 NestJS 설계와 `/v1/auth/exchange`·`/v1/auth/refresh`·`/v1/auth/logout` 계약을 사용한다. 서버가 제공자 자격 증명과 제공자 고유 ID를 검증하고 BugMap 내부 사용자 ID와 앱 세션을 발급한다. 기존 API가 연결되면 재사용하고, 제공되지 않으면 최소 로그인·세션 API를 구현하는 단계를 포함한다. [TDD 인증 설계](../../TDD.md#61-모바일-앱-로그인세션)
3. 앱은 액세스 토큰은 메모리, 갱신 토큰은 OS의 보안 저장소를 사용한다. 앱 재실행 후 유효한 세션은 복구한다. 갱신이 일시적으로 실패하면 저장된 갱신 토큰을 유지하고 재시도를 표시한다. 서버가 갱신 토큰의 만료 또는 세션 폐기를 확인하면 로그인 화면을 다시 연다. 로그아웃은 서버 세션 폐기와 기기 저장값 삭제를 확인한다. 동일 이메일의 다른 제공자 계정은 제공자 고유 ID를 기준으로 처리한다.
4. 출시용 제공자 자격 증명과 테스트 계정은 승인된 앱 설정·보안 저장 방식으로 연결한다. `이용약관`과 `개인정보처리방침`을 각각 밑줄 링크로 두고 게시 후 해당 공개 문서를 연다. 게시 전에는 선택한 문서 이름과 준비 상태를 표시한다. 신규 가입은 로그인 화면에서 정책 링크를 열람할 수 있는 흐름으로 진행한다. 계정 연결·복구·삭제와 전체 배포는 연관된 제품 범위이며 각각의 요구사항을 별도로 충족해야 한다.

## 수용 기준

- **Figma와 UI.** BugMapHarness의 05에서 확인한 배경·로고·본문·공식 버튼·정책 링크를 대조한다. 390×844 및 360×800, 글자 확대와 화면 읽기에서 버튼·약관·출처가 눌리거나 읽힌다. iOS에는 세 제공자, Android에는 두 제공자가 표시된다.
- **지도.** 로그인 스냅샷과 기본 메인 지도의 기준 카메라·스타일을 비교한다. 로그인 화면에서 지도 엔진 초기화나 위치 권한 요청 없이 버튼을 사용할 수 있고, 이미지 로드 실패 시에도 화면을 조작할 수 있다.
- **인증.** 앱·서버에서 각 OS 지원 제공자의 로그인 성공, 취소, 네트워크 실패·재시도, 중복 탭, 정책 링크별 열람 또는 게시 준비 상태, 재실행 시 세션 복구와 네트워크 재시도, 만료·로그아웃을 확인한다. 자동 테스트 결과와 테스트 계정으로 확인한 실제 제공자 흐름을 구분해 기록한다.
- **전달.** 승인 이후 Coding Agent는 GPT-6.2 Sol로 작업하고, Testing Agent는 GPT-6.2 Astra로 같은 후보 커밋을 독립 검증한다. 리뷰와 사람 승인은 [개발·배포 워크플로](../../development-workflow.md)를 따른다.
