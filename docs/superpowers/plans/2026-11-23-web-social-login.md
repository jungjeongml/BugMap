# 웹 소셜 로그인

## 수용 기준

- 웹 첫 화면의 카카오와 Google 버튼에서 실제 제공자 인증 페이지로 이동한다.
- 제공자의 동의와 BugMap 세션 확인이 끝나면 발견 지도가 표시된다. 취소하거나 연결에 실패하면 첫 화면에서 다시 시도할 수 있다.
- 새로고침해도 유효한 세션을 복구하고, 로그아웃하면 서버 세션을 폐기한다.
- 기존 iOS·Android 앱의 복귀 주소, 토큰 교환, 세션 동작을 계속 지원한다.

## 구현

1. 첫 화면이 현재 탭에 일회용 state와 S256 PKCE 검증값을 보관하고 공개 HTTPS 인증 서버에서 제공자 인증을 시작한다.
2. 카카오·Google의 등록 콜백은 기존 서버 경로를 사용한다. 서버는 제공자 응답과 시작 브라우저를 검증한 뒤, 고정된 웹 주소로 BugMap 일회용 코드나 실패 상태를 반환한다.
3. 웹 클라이언트가 복귀 주소에서 인증 파라미터를 지우고, 동일 출처 API에서 BugMap 코드를 교환한다. 웹 세션은 HttpOnly 쿠키로 확인한다.
4. Expo 개발 서버는 웹 교환·세션·로그아웃 요청을 로컬 인증 서버로 전달한다. 배포 환경에는 동일 출처 리버스 프록시가 필요하다.

## 역할 및 검증

- Planning에서 웹·네이티브 복귀 경로, 동일 출처 쿠키, 세션 복구, 취소 상태의 수용 기준을 정한다.
- Sol이 앱과 서버를 구현한다. Astra가 인증·서버 테스트와 세션 경계를 독립 검토한다.
- 브라우저에서는 테스트 제공자를 사용해 코드 교환부터 지도 표시·새로고침·로그아웃을 검증한다. 공개 개발 서버에서는 콘솔 등록이 확인된 제공자의 실제 인증 진입과 실제 계정 완료를 각각 기록한다.
